# Dungeon of the Basilisk

Dungeon of the Basilisk is a local turn-based board game for 1 to 6 players. Players move from the outer paths toward the central basilisk while encountering corridors, quiz doors, monsters, and the final boss.

The game runs in the browser, stores teacher-edited questions locally, and does not require a backend, account, API key, or external game service.

## Features

- Local multiplayer for 1 to 6 players.
- Multilingual UI support: English, Polish, Ukrainian, Russian, and Japanese.
- SVG-rendered board and animated dice.
- Quiz questions for door encounters.
- Rock-paper-scissors encounters for monsters and the boss.
- Local teacher question editor with import/export and local image library support.
- Standalone production build through `vite-plugin-singlefile`.

## Tech Stack

- React 19
- TypeScript
- Vite
- Vitest
- vite-plugin-singlefile

## Getting Started

Prerequisites:

- Node.js
- npm

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Run quality checks:

```bash
npm run typecheck
npm run test:run
npm run build
```

## Available Scripts

- `npm run dev` starts the Vite development server.
- `npm run typecheck` runs TypeScript without emitting files.
- `npm test` starts Vitest in watch mode.
- `npm run test:run` runs Vitest once.
- `npm run build` creates the production build in `release/`.
- `npm run preview` previews a production build locally.

## Project Structure

- `App.tsx` contains the main game flow and UI composition.
- `components/` contains React components for the board, dice, teacher editor, and image tools.
- `gameUtils.ts` contains pure game utility functions covered by unit tests.
- `questionBank.ts`, `questionStorage.ts`, `questionValidation.ts`, and `questionSubjects.ts` contain local question bank logic.
- `dictionary.ts` contains localized game text.
- `korytarzeidrzwi/` contains bundled game images used by the app.
- `release/` is generated by `npm run build` and is ignored by Git.

## Repository Notes

The production build is intentionally not stored in the repository. Generate it locally with `npm run build` when needed.

The current `index.html` loads Tailwind from a CDN. The game logic and local data features do not require a backend, but a fully offline packaged distribution would need a separate styling-packaging pass.
